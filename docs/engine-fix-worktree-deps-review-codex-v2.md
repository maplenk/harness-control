# Codex re-review of F7 worktree-deps spec v2 (2026-07-22)

Verdict: NEEDS-REVISION (3 blockers + 4 high). Extracted from codex job re-review.

## 1. Prioritized residual holes

1. **BLOCKER — Provisioning occurs before, not after, dependency-manifest edits.** The normal flow creates the worktree before the implementor runs ([orchestrate.ts:472](/Users/tagtaste/Documents/QBApps/harness-orchestration/src/app/flows/orchestrate.ts:472)); the implementor can then change manifests, commits them ([implementor.ts:910](/Users/tagtaste/Documents/QBApps/harness-orchestration/src/app/flows/implementor.ts:910)), and immediately executes host verification ([implementor.ts:927](/Users/tagtaste/Documents/QBApps/harness-orchestration/src/app/flows/implementor.ts:927)). No proposed adoption hook runs in between, and independent verification follows without provisioning ([orchestrate.ts:701](/Users/tagtaste/Documents/QBApps/harness-orchestration/src/app/flows/orchestrate.ts:701)). Additionally, the marker and clone decision hash only `package-lock.json` ([spec:52](/Users/tagtaste/Documents/QBApps/harness-orchestration/docs/engine-fix-worktree-deps-spec.md:52)), so a `package.json`-only edit still short-circuits or clones stale primary dependencies. Required: provision after the implementor commit and immediately before both host and verifier command execution; bind at least root/workspace `package.json`, lockfile, project `.npmrc`, install flags, and platform/tool versions. Primary `node_modules` absence must trigger install when manifests declare dependencies—not “skip” as specified at [spec:51](/Users/tagtaste/Documents/QBApps/harness-orchestration/docs/engine-fix-worktree-deps-spec.md:51).

2. **BLOCKER — AC-4 is not mechanically enforceable by the proposed design.** Host outcomes contain no binary path/version/provisioning attestation ([implementor.ts:134](/Users/tagtaste/Documents/QBApps/harness-orchestration/src/app/flows/implementor.ts:134)); the runner inherits ambient `PATH` ([implementor.ts:256](/Users/tagtaste/Documents/QBApps/harness-orchestration/src/app/flows/implementor.ts:256)) and defines pass solely as exit zero ([implementor.ts:946](/Users/tagtaste/Documents/QBApps/harness-orchestration/src/app/flows/implementor.ts:946)). More importantly, merge readiness trusts the verifier’s nonempty narrative evidence ([verifier.ts:478](/Users/tagtaste/Documents/QBApps/harness-orchestration/src/app/flows/verifier.ts:478)); “required tests passed” checks only `verdict === passed` plus an evidence ref ([verifier.ts:1072](/Users/tagtaste/Documents/QBApps/harness-orchestration/src/app/flows/verifier.ts:1072)). A nonfatal provisioning failure ([spec:57](/Users/tagtaste/Documents/QBApps/harness-orchestration/docs/engine-fix-worktree-deps-spec.md:57)), global binary, cached/downloaded `npx` package, or forged writable marker can therefore still green the run. Required: host-generated, structured provenance bound to the dependency fingerprint and command result; fail closed before verifier dispatch when provisioning is unproved; prohibit `npx` installation/cache fallback; and rebuild or integrity-check the agent-writable tree before trusting it.

3. **BLOCKER — The transaction is not implementable as written.** POSIX rename cannot replace an existing nonempty directory, so “atomic rename replacing prior tree” at [spec:56](/Users/tagtaste/Documents/QBApps/harness-orchestration/docs/engine-fix-worktree-deps-spec.md:56) fails with `ENOTEMPTY` ([POSIX rename](https://pubs.opengroup.org/onlinepubs/9799919799/functions/rename.html)). `npm ci` also automatically removes an existing `node_modules` before installation ([npm ci documentation](https://docs.npmjs.com/cli/commands/npm-ci/)). Furthermore, `node_modules.tmp-*` is not matched by the exact [`node_modules/` rule](/Users/tagtaste/Documents/QBApps/harness-orchestration/.gitignore:1); a crash can leave it for the implementor’s unconditional `git add -A` ([git.ts:207](/Users/tagtaste/Documents/QBApps/harness-orchestration/src/worktree/git.ts:207)) or validation WIP commit ([validate.ts:152](/Users/tagtaste/Documents/QBApps/harness-orchestration/src/worktree/validate.ts:152)). Required: staging/backup outside the Git worktree but on the same filesystem, an explicit move-aside/move-in/rollback state machine, crash recovery for abandoned staging/backups, and marker-write failure handling.

4. **HIGH — COW cloning does not eliminate symlink write-through.** macOS `cp -R` preserves symlinks, while `-c` changes regular-file copying to clonefile ([macOS `cp(1)`](https://keith.github.io/xcode-man-pages/cp.1.html)). Relative `.bin` links remain relative and correctly resolve within the clone; absolute or escaping relative links remain pointed at the primary/outside tree. The spec does not `lstat` the primary `node_modules` root or scan copied links. Writes through such links are invisible to the primary drift guard because Git collapses the ignored primary directory to the same `!! node_modules/` status entry ([implementor.ts:458](/Users/tagtaste/Documents/QBApps/harness-orchestration/src/app/flows/implementor.ts:458), [implementor.ts:506](/Users/tagtaste/Documents/QBApps/harness-orchestration/src/app/flows/implementor.ts:506)). This checkout currently has relative `.bin` links and no inspected absolute links, but the engine supports arbitrary target repos. Require real-directory roots plus a post-clone/post-install symlink containment scan. Also purge cloned `.vite` state; otherwise writes are isolated, but stale cache contents are still inherited—false-result impact remains a hypothesis.

5. **HIGH — Locking coverage remains incomplete.** `reattach` currently performs path validation and handle registration outside both locks ([manager.ts:309](/Users/tagtaste/Documents/QBApps/harness-orchestration/src/worktree/manager.ts:309)); `reacquireLease` is synchronous and unlocked ([manager.ts:286](/Users/tagtaste/Documents/QBApps/harness-orchestration/src/worktree/manager.ts:286)). A separately locked `ensureProvisioned()` does not make those transitions atomic, and provisioning must occur after `discardToCommit` changes the manifest ([orchestrate.ts:377](/Users/tagtaste/Documents/QBApps/harness-orchestration/src/app/flows/orchestrate.ts:377)). Verifier failover/auto-respawn explicitly skips the implementor branch ([orchestrate.ts:543](/Users/tagtaste/Documents/QBApps/harness-orchestration/src/app/flows/orchestrate.ts:543)) and therefore bypasses `ensureLeased`, the only cited reacquisition point ([orchestrate.ts:853](/Users/tagtaste/Documents/QBApps/harness-orchestration/src/app/flows/orchestrate.ts:853)). Required: composite async manager operations that reconcile/reset, provision, and register/reacquire under one mutex+advisory lease, plus an unconditional pre-dispatch ensure for both roles—including already-leased handles.

6. **HIGH — Automatic `npm ci` adds unsandboxed host execution.** `npm ci` runs install lifecycle scripts by default ([npm scripts documentation](https://docs.npmjs.com/cli/using-npm/scripts/)); those scripts may be changed by the implementor. The code already documents that host-shell execution lacks filesystem/network confinement ([implementor.ts:73](/Users/tagtaste/Documents/QBApps/harness-orchestration/src/app/flows/implementor.ts:73)), while the spec explicitly assumes network access ([spec:75](/Users/tagtaste/Documents/QBApps/harness-orchestration/docs/engine-fix-worktree-deps-spec.md:75)). Define minimal environment, credential stripping, timeout/process-group cleanup, filesystem/network confinement, and whether install scripts are disabled or explicitly allowed.

7. **MEDIUM — Git invisibility is proved only for this repository.** Here, a real directory is ignored by [`.gitignore:1`](/Users/tagtaste/Documents/QBApps/harness-orchestration/.gitignore:1), so plain status/diff, `git add -A`, the implementor commit, and WIP reconciliation omit it; `discardToCommit` invokes `git clean -fd` without `-x` ([git.ts:249](/Users/tagtaste/Documents/QBApps/harness-orchestration/src/worktree/git.ts:249)), so it survives as confirmed by [Git’s clean semantics](https://git-scm.com/docs/git-clean). But the test-matrix cases “no ignore rule” and “tracked node_modules” have no defined safe result: `add -A` will stage the former and provisioning can modify the latter. Require a `check-ignore`/`ls-files` preflight and fail closed.

Confirmed non-holes: with a real COW directory, current `git worktree remove --force` reaches only the worktree path ([manager.ts:428](/Users/tagtaste/Documents/QBApps/harness-orchestration/src/worktree/manager.ts:428), [git.ts:199](/Users/tagtaste/Documents/QBApps/harness-orchestration/src/worktree/git.ts:199)); no production raw recursive removal of `baseDir` exists. Recursive deletion does not follow internal symlinks, so primary deletion is fixed, although runtime write-through is not. Marker placement itself is harmless to npm if written after `npm ci`; its trust/integrity semantics are the problem.

## 2. Verdict

**NEEDS-REVISION.** Required changes: move provisioning to a post-implementor/pre-verification boundary; bind the full install inputs and validate the clone source; enforce provenance in runtime data and merge-readiness logic; replace the impossible rename description with a recoverable out-of-worktree swap; contain symlinks and purge caches; make all adoption/redrive operations composite and locked; define npm lifecycle confinement; and fail closed for unignored/tracked dependency paths.

## 3. Must-add ACs/tests

- Package-only, lock-only, both-manifest, workspace-manifest, and `.npmrc` changes between creation and verification; assert reprovision occurs after commit.
- Primary dependencies absent, hollow, stale/wrong-version, root symlink, or changed concurrently; never clone an unproved source.
- Global `tsc`/`vitest`, populated npx cache, network-available npx, forged marker, modified local binary, and `{provisioned:false}`; none may produce `passed`.
- Relative `.bin` link, safe workspace-relative link, absolute link to primary, escaping relative link, and symlinked primary root; unsafe cases must fall back or fail closed.
- Existing nonempty destination plus failures/crashes after backup, install, move-in, and marker write; recover on the next call with no stage/backup path visible to Git.
- Fresh verifier, verifier failover, verifier auto-respawn, implementor failover with an already-leased handle, and resume after `discardToCommit`; assert ensure runs after final manifest state.
- No-ignore and tracked-`node_modules` repositories: explicitly fail closed and assert neither dependencies nor staging artifacts enter any commit.
- Clone containing `.vite`; assert transient caches are removed rather than inherited.
